# Security

Curve is experimental browser software. This document describes the **0.4 release candidate**, which adds security/privacy hardening and adversarial regression checks but has not received an independent security audit. The stable public download remains **0.3.1**, lacks these changes, and is ad hoc signed without Apple notarization. Public distribution of 0.4 is pending Developer ID signing and notarization. Do not assume security parity with Chrome, Safari or Brave, or rely on it for high-value accounts on the strength of functional tests alone.

Website execution uses Apple's WebKit runtime. Keep Apple software updated for engine fixes; Curve's own native code also needs app updates. The isolated interaction bridge exposes only bounded browser interactions, not filesystem/shell/credential APIs. Certificate checks and fraudulent-site warnings remain enabled. Production web inspection is disabled.

The packaged app uses Hardened Runtime and App Sandbox with outgoing network, user-selected files, camera and microphone capabilities. It has no broad home-folder, server, JIT, debugger, unsigned-memory or disabled-library-validation entitlements. Website file/media requests require visible, current documents; cross-origin media frames are denied, and pending native requests are rejected on navigation/close/reset. Downloaded files must retain macOS quarantine metadata. The unpackaged `swift run` binary does not inherit the app bundle's sandbox policy.

Private windows are the default and use nonpersistent website stores; tabs/history are not saved. Persistent windows are an explicit choice and share website logins across Spaces. Private mode does not hide traffic from websites/search/network providers, prevent user-selected exports/downloads, or guarantee erasure of OS swap, snapshots or external backups.

Persistent metadata uses owner-only directories/files and descriptor-relative atomic operations that reject symlink/hardlink substitution and remove extended ACL grants. Full URLs and titles are still stored as JSON in persistent mode: this is access control, not app-level encryption. Clear-data operations remove known recovery copies and coordinate active windows; previously exported files and older unsandboxed profiles remain outside the current sandbox.

Ad/tracker lists are bundled, pinned by source revision and SHA-256, and compiled into native WKContentRuleLists before page loads. Missing/altered rules stop navigation. No remote filter configuration or browsing-address upload is used. This does not guarantee that every advertisement, tracker or phishing site will be blocked. GPC is a request to sites, not enforcement or anonymity.

The update checker only checks the official GitHub endpoint on user request and opens a validated release-page URL. It does not automatically install code. A Developer ID certificate and Apple notarization are prerequisites for normal trusted distribution; notarization is an automated malware/signature check, not an independent browser security audit.

Useful adversarial test areas include hostname/IDNA presentation, unfiltered startup races, cookie/history restoration after clearing, stale permission dialogs and file panels, download quarantine, unsafe URL schemes, certificate failures, and sandbox escape attempts against synthetic fixtures. See `run-checks.sh`, `Checks/ProtectionChecks.swift`, `Checks/PrivacyIntegrationChecks.swift`, `Checks/PrivacyStorageChecks.swift`, and `Checks/SandboxChecks.sh`. Passing these finite tests does not establish absence of exploitable bugs.

For a non-sensitive bug, open a repository issue with a reproducible synthetic example. Do not include passwords, cookies, browser profile files, authentication tokens, private website URLs, or unfinished personal documents in public reports. Security-sensitive findings should be shared through an existing private channel with the Toymakers maintainers rather than posted publicly.
